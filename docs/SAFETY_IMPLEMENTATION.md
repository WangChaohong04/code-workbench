# 软件工程安全控制层

## 当前范围

工作台只保留软件开发任务、结构化契约、候选代码副本、权限审批、冻结、审计和结果状态。旧的通用研究、采购、支付、通知、地图、天气、汽车场景已从产品入口移除；历史数据库与用户导入资料不删除。

## 执行路径

用户需求 → 开发任务（只读）→ 用户确认工程契约 → 候选副本与差异。

后续测试执行、合并、生产发布、数据库迁移和恢复执行器尚未接入，保持关闭；不能将候选生成称为开发任务完成。

## 控制边界

- API 的身份取自服务端认证，契约确认取实际所有者身份，冻结/解冻要求管理员。
- ToolRuntime 检查契约、风险、审批并在执行前复查；未知工具不得通过声明自行获得可信资格。
- 全局冻结递增 epoch 并撤销旧审批；解冻不恢复旧授权。
- 候选副本不覆盖源目录，未配置独立目录时拒绝生成；候选文件不会自动执行。
- events 追加且有 UPDATE/DELETE 防改触发器，写入前脱敏。
- 执行、验证、代码恢复、配置恢复与数据恢复分开记录。
- 不自动加载本地 Python 插件；SDK 保留为工程基础设施，不构成不可信代码隔离。

## 已知限制

冻结是协作式控制，不保证中断已发出的外部请求。候选副本不是 OS 沙箱。数据库管理员和宿主机管理员可绕过应用权限，SQL 触发器不是独立审计存储。当前没有真实发布后验证和数据库恢复演练。测试通过只证明所覆盖的行为，不证明生产可用。

## 事故处理

1. 点击全局冻结，停止新的受控写入；必要时由运维在外部系统撤销执行凭据。
2. 保留任务 ID、审批、epoch、日志及候选差异，不删除数据库或重写历史。
3. 将已经发出的副作用视为待确认，向权威系统核实，不盲目重试。
4. 分别确认代码版本、配置版本、数据库状态，不以代码回滚代替数据恢复。
5. 在独立环境验证修复/恢复方案，再按人工运维流程审批执行。
6. 解冻后重新确认契约和审批；不得自动恢复旧操作。
